# 部署與維運手冊(Phase 8 — 上線硬化)

> 對象:把系統部署到自家 NAS 並安全上線。每一項都先說「為什麼」,再給做法。
> 對應 `01_系統架構與技術建議.md` §7 資安檢查清單。

---

## 0. 架構回顧(對外只露一個門)

```
裝置(筆電/平板/手機) ──HTTPS──> Caddy(唯一對外:80/443)
                                  ├─ /api/*  → backend(Flask+gunicorn:8000)
                                  └─ 其餘     → frontend(nginx 靜態檔:80)
                                              backend ── db(PostgreSQL,僅內網)
                                              backend ── CUPS(列印)
```

**原則**:`frontend / backend / db` 都只在 Docker 內網,**不對公網開埠**;安全邊界只有 Caddy。

---

## 1. 正式環境 `.env`(機密不進 git)

```bash
cp .env.example .env
```
務必修改:
- `POSTGRES_PASSWORD`:強密碼。
- `DATABASE_URL`:用**最小權限**的 DB 帳號(見 §6),不要用 superuser。
- `SECRET_KEY`:`python -c "import secrets;print(secrets.token_hex(32))"`。
- `SESSION_COOKIE_SECURE=true`(走 HTTPS)。
- `TRUST_PROXY=true`(後端在 Caddy 後,才能取得真實 client IP 做 rate limit / audit)。
- `SITE_ADDRESS=你的網域`(Caddy 會自動申請 Let's Encrypt 憑證)。
- `RATELIMIT_STORAGE_URI=redis://redis:6379`(多 worker 共用限流;見 §5)。
- `ARCHIVE_DIR=/archive`、`CUPS_*` 佇列名稱、公司抬頭。

---

## 2. 用正式 compose 起整套(NAS)

本機開發有 `docker-compose.override.yml`(會把 db 對外開 5433),**正式環境不要套用它**:

```bash
# 只用基底 compose(忽略 override)
docker compose -f docker-compose.yml up -d --build
```

- Synology 用 **Container Manager**、QNAP 用 **Container Station**,或直接 SSH 跑上面指令。
- **DB 資料掛 NAS 實體路徑**:把 `docker-compose.yml` 裡 db 的
  `./pgdata` 改成例如 `/volume1/docker/shitian/pgdata`,並納入 NAS 自身的快照/備份。
- 後端啟動會自動跑 `flask db upgrade`(migration),不必手動進容器。
- 第一次要建管理員:
  ```bash
  docker compose exec backend flask create-admin --username admin --display-name 管理員
  ```

---

## 3. Caddy / HTTPS

`Caddyfile` 已用 `{$SITE_ADDRESS}`:
- 填**網域** → Caddy 自動申請 / 續期 Let's Encrypt 憑證,**HTTP 自動轉 HTTPS**。
- 填 `localhost` → 用內建 CA 自簽(本機測試用)。
- 需求:網域 DNS 指到這台 NAS 的公網 IP,且 80/443 能被 Let's Encrypt 連到(VPN-only 方案見 §4 用內部憑證或 DNS 驗證)。

---

## 4. 遠端存取(資安優先:VPN-only)

**首選:Tailscale / WireGuard,只走 VPN,不開公網。**
- 在 NAS 安裝 Tailscale,裝置加入同一 tailnet,用 NAS 的 tailscale IP/MagicDNS 存取。
- 好處:完全不曝露 443 到公網,攻擊面最小。
- 此時 Caddy 可用內部憑證或 Tailscale 提供的憑證。

**若真的要開公網**(次選),至少:
- 只開 443(80 僅供憑證驗證後轉址)。
- `fail2ban` 擋暴力嘗試。
- 應用層 rate limit(login 已內建;§5 換 Redis)。
- 定期更新映像與套件。

---

## 5. rate limit 用 Redis(正式)

開發用記憶體儲存(會有警告、且多 gunicorn worker 各算各的)。正式環境在 compose 加一個 redis 服務並設 `RATELIMIT_STORAGE_URI=redis://redis:6379`:

```yaml
  redis:
    image: redis:7-alpine
    restart: unless-stopped
    expose: ["6379"]
```

---

## 6. DB 最小權限帳號(不要用 superuser)

postgres 映像第一次啟動時用 `POSTGRES_USER` 建的帳號是該 DB 的 owner。若要更嚴格,可另建只有 CRUD 權限的應用帳號:

```sql
-- 以管理帳號連入後執行
CREATE USER shitian_app WITH PASSWORD '強密碼';
GRANT CONNECT ON DATABASE shitian TO shitian_app;
GRANT USAGE ON SCHEMA public TO shitian_app;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO shitian_app;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO shitian_app;
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO shitian_app;
-- migration(建表)用較高權限的帳號跑,平時 DATABASE_URL 用 shitian_app。
```

---

## 7. 列印(CUPS)接線

後端用 `lp` 送印,需要連到 CUPS:
- **CUPS 跑在 NAS**:把 host 的 CUPS socket 掛進 backend 容器,或設 `CUPS_SERVER` 指向 CUPS 主機:
  ```yaml
  backend:
    volumes:
      - /var/run/cups/cups.sock:/var/run/cups/cups.sock
  ```
- 在 CUPS 建兩個佇列:`normal`(一般雷射/噴墨)與 `dotmatrix`(點陣機,raw/ESC-P)。
- 點陣套表先用「主檔 → 套表校正」下載校正頁,印在三聯單上量測、調 offset、重印對準。

## 8. 每日備份(3-2-1)

`scripts/backup.sh` 用 `pg_dump` 備份並壓縮、保留最近 14 天:

```bash
sh scripts/backup.sh                 # 產生 backups/shitian-YYYYmmdd-HHMMSS.sql.gz
```

設 cron 每日 02:00 自動跑(NAS 的排程或 crontab):
```
0 2 * * * cd /volume1/docker/shitian && sh scripts/backup.sh >> backups/backup.log 2>&1
```
**3-2-1**:本機一份 + NAS 快照一份 + 另存異地/外接一份。

還原:
```bash
sh scripts/restore.sh backups/shitian-YYYYmmdd-HHMMSS.sql.gz
```
> 上線前請**實際還原一次**到測試庫,確認備份可用(備份沒驗證過 = 沒有備份)。

## 10. CD / 映像自動更新(GitHub Actions → GHCR)

CI(`.github/workflows/ci.yml`)負責「驗證」,CD(`.github/workflows/cd.yml`)負責「建映像並推到 GHCR」。**目前部署是半自動**:CD 把映像推上去,各機器自己 `pull` 更新。

**分支 → 環境對應:**

| 分支 | 推出的標籤 | 給哪台 |
|---|---|---|
| `main` | `:prod`、`:prod-<sha>`、`:latest` | 正式 NAS |
| `develop` | `:dev`、`:dev-<sha>` | dev 機器 |

**一次性設定:**
1. GHCR 套件預設 private,**每台部署機器**先登入(PAT 需 `read:packages`):
   ```bash
   echo <PAT> | docker login ghcr.io -u frank931023 --password-stdin
   ```
   (或在 GitHub 把 `shitian-backend`/`shitian-frontend` 兩個套件設為 public,就免登入。)

**更新流程(改完 code、push 後):**
```bash
# 正式 NAS(main 推上去後)
cd /volume1/docker/shitian && git pull          # 取得最新 compose 設定
IMAGE_TAG=prod docker compose \
  -f docker-compose.yml -f docker-compose.prod.yml -f docker-compose.images.yml pull
IMAGE_TAG=prod docker compose \
  -f docker-compose.yml -f docker-compose.prod.yml -f docker-compose.images.yml up -d
```
```bash
# dev 機器(develop 推上去後)— 不套 prod.yml
IMAGE_TAG=dev docker compose \
  -f docker-compose.yml -f docker-compose.images.yml pull
IMAGE_TAG=dev docker compose \
  -f docker-compose.yml -f docker-compose.images.yml up -d
```
- `docker-compose.images.yml` 把 backend/frontend 改成拉 GHCR 映像(不在機器上重 build)。
- backend 啟動會自動 `flask db upgrade`,migration 不必手動跑。
- 要回滾:把 `IMAGE_TAG` 換成某個 `prod-<sha>` 舊標籤再 `up -d`。

> 想完全自動(push 完 NAS 自己更新)有兩條路:在 NAS 跑 self-hosted runner,或裝 watchtower 監看映像更新。VPN-only 的 NAS 建議走 self-hosted runner,不必對外開埠。

## 11. 日常維運清單

- **每日**:看備份 log 有成功;偶爾看應用日誌 `docker compose logs -f backend`。
- **每月**:更新映像 `docker compose pull && up -d --build`、更新相依套件、檢查磁碟空間(archive/backups)。
- **每季**:做一次還原演練;檢視 audit_log 有無異常操作。
